Where this lands in Firefox code

The lab uses reimplementations of Acorn toolkit widgets (moz-button, moz-card, moz-badge, moz-toggle — see moz-components.js) so markup reads like in-tree code. Proposed integration points:

browser/components/aiwindow/
  AgentEngine.sys.mjs        ← engine.js (surface-independent core;
                               checks via nsIUpdateTimerManager)
  content/smart-window.html  ← panel: Chat + Shelf segments
  content/agent-objects.mjs  ← shelf cards, plan cards (lit, like
                               toolkit/content/widgets/*)

browser/base/content/
  waypoints.mjs              ← Tab Context Badge anchored to the
                               watched element (AnonymousContent
                               overlay, same mechanism as the
                               find-highlighter — survives page CSS)

tabbrowser:
  sleeping tab = existing unloaded-tab state + a "wake on
  condition" attribute; badge via tab.setAttribute("attention")

toolkit/components/alerts:
  watch-hit notifications route through nsIAlertsService;
  fallback chain: alert → tab attention → shelf badge

Tokens: all colors/spacing/motion consume Acorn tokens
(sidebar.css, common.css) + Smart Window motion tokens
(ai-window-motion.css — the SOT in this repo).

The "LLM read" is simulated with deterministic price paths (engine.js → PATHS) so every demo lands. The production contract stays the same: the model returns structured rule-state, never free text, and alerts only fire on validated numbers — the injection-hardening amendment from the red team.
